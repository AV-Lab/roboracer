## 3. F1-1 第 1 次试验 — 扫描缺失（`artifacts/s1/20261006T064801Z-m1-f1/f1-1-t1*`）

注入发生在 run 时间 6.10 s，车辆以 0.27 m/s 行驶在直道上。时间线（注入后的毫秒数，主机单调钟）：

| t | 事件 |
| --- | --- |
| 0 | 栈写出冻结请求（桥接在下一次节奏化回复中发送） |
| +344 | 最后一个有效快照（其扫描在冻结前刚刚采集） |
| +552 | 第一个 LiDAR 被冻结（复用）的遥测帧 |
| +601 / +701 | 监督器仍在转发：观测年龄 348 / 449 ms，低于 500 ms 限制 |
| +816 | 守卫接受最后这个请求及其剩余租约 |
| +801 起 | 监督器拒绝所有请求：`stale-observation` |
| +1000 | 栈以“0.60 s 内无新观测”中止，并请求零速（按设计，因观测过期被拒绝） |
| +1124 | 守卫：`state stopped lease-expired`；油门归零 |
| +1391 / +1606 | 帧显示车辆先减速、后静止；帧间隔约 215 ms |

| 冻结的检查 | 结果 |
| --- | --- |
| 快照因 `scan/pose skew` 被拒绝；栈因无新观测中止；监督器 `stale-observation` | **通过** |
| 注入后行驶 ≤ 0.40 m | **通过**：0.358 m |
| 无接触、无出界；无守卫故障；所有进程已回收；播放器未改变 | **通过** |
| 注入后 1.5 s 内停车 | **未通过**：1.606 s（首个静止帧） |
| 注入 + 1.1 s 后无非零油门 | **未通过**：油门 0.0585 持续到 +1124 ms |
| 最后一个有效快照后 ≤ 0.6 s 中止（我分析中用的值；协议文本为 0.5 s） | **未通过**：0.656 s |

**原因：是协议缺陷，不是系统缺陷。** 协议从栈*请求*故障的时刻开始计时，而扫描缺失要等仿真器响应该请求后才开始：晚 0.35–0.55 s，因为请求要搭乘下一次节奏化回复和下一次采集。此后，已确认的限制本身还允许：
- 最多 500 ms 的观测年龄；
- 500 ms 的请求寿命；
- 约 0.2 s 的制动；
- 最多一帧（约 0.2 s）之后才观测到停车。

因此设计上的最坏情况约为请求后 1.7 s，1.5 s / 1.1 s 两项检查对 F1-1 不可能成立。0.5–0.6 s 的中止检查同样忽略了栈 100 ms 的 tick：其规则在“最后一次看到新快照的 tick”之后超过 0.5 s 的第一个 tick 触发，即可能在该快照后约 0.7 s 才触发。

从故障**生效**（第一个冻结帧，+552 ms）起算：
- 守卫的最后一个非零油门在 +0.57 s；
- 车辆在下一帧即静止，即 1.05 s 后；
- 各层均按设计顺序动作。
