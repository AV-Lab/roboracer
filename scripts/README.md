# Simulator qualification tools

These are explicit engineering entrypoints, outside the default plugin execution flow. Importing a tool must not start a process, parse command-line arguments, install dependencies or create files. The current scope is SIM0 and its separately approved diagnostics; no driving plugin or SIM1 feature is implemented here.

## Pinned AutoDRIVE build

`autodrive_build.py` wraps the Unity 2021.3 batch import/build interface. It checks the pinned project revision, engine setting, enabled F1TENTH scene and IL2CPP setting, then records the invocation, input hashes, source changes, Editor resource counters, exit/cleanup state and output hashes. Raw Unity logs are private because they can include licensing metadata. A successful exit is not stage acceptance.

Use a complete, separately owned checkout of `635dbb6d86ec98e25ea845a97188f7bbe85a09e8`, Unity **2021.3.9f1 / ad3870b89536**, and Linux IL2CPP support. Resolve the host toolchain using the reviewed package diff; do not silently upgrade packages or engine versions. The agent does not activate a license or accept a different entitlement through this tool.

Example using the current isolated SIM0 paths:

```bash
python3 scripts/autodrive_build.py \
  --editor /tmp/roboracer-work/toolchains/2021.3.9f1/Editor/Unity \
  --project /tmp/roboracer-work/autodrive-635dbb6d-baseline \
  --output /tmp/roboracer-work/autodrive-builds/baseline-example \
  --results artifacts/simulator-build/example/build \
  --timeout 3600
```

Choose fresh output/result paths for each recorded attempt. Add `--import-only` to qualify package resolution/initial import separately; this mode does not create a player. The timeout is an execution bound, not an accepted build-performance target. `-nographics` applies to Editor compilation/import only and does not qualify camera sensing without a display.

On this Ubuntu 22.04 host, the pinned Editor's bundled .NET 5.0.3 compiler failed with `No usable version of libssl was found`. A fresh empty-project batch check passed after extracting Ubuntu's authenticated `libssl1.1` package into private scratch. Add `--native-library-dir /tmp/roboracer-work/sim0-20260929T085557Z/openssl-compat/extracted/usr/lib/x86_64-linux-gnu` to the command above for this qualified dependency setup. The tool records library hashes and changes the environment only for its Editor subprocess. It does not install system packages, modify Hub or affect projects launched directly from Hub. Package origin/signature/hash evidence is in `artifacts/simulator-build/20260929T085557Z/openssl-compatibility-dependency.json`. This is a tested compatibility configuration, not a general supported-host claim.

After invocation, inspect the private diagnostics and `source-after.patch`; unresolved references, compilation/build errors or unapproved scene/physics/package changes block acceptance. SIM0 also requires two fresh-process, 60-second neutral observations through the qualified Humble/AVLite environments and their cleanup/geometry comparison. Follow the [stage contract](../docs/planning/simulator-build-amendment.md) and [current PRE status](../docs/stages/PRE.md).

Use `--audit-scene` instead of `--import-only` for a bounded dependency inspection. The wrapper stages `SceneDependencyAudit.cs` temporarily under the separate checkout's `Assets/Editor/`, invokes its explicit static method, writes `scene-audit.json` and removes the owned probe/metadata afterward. It does not enter Play mode, save the scene or build a player. The dependency set is static evidence; dynamic loading and actual sensor behavior still need runtime qualification. The first audited import illustrates why exit 0 alone is insufficient: see the [import review](../docs/stages/SIM0-import-review.md).

The toolchain, complete third-party project, Unity `Library`, caches, binaries and raw run artifacts stay outside versioned plugin code. `/tmp/roboracer-work/` is disposable scratch and may need reconstruction after cleanup or reboot. Preserve code/dependency fingerprints and notices with the evidence; do not commit downloaded Unity or simulator assets.

## Stationary observations

`autodrive_neutral.py` reuses the isolated, qualified Humble Devkit and AVLite environments named by a context file. Its `run` mode creates fresh player/bridge/observer processes for each trial, with 1280×720 graphics, zero-only Socket.IO replies and the recorded 100 ms diagnostic reply delay. The default is two 60-second observation windows after complete bridge and eight-topic ROS observations. This is a stationary transport check, not a throughput or braking benchmark.

The runner pauses for review of each owned window's `ui-before-connect.png`. An operator must inspect Manual mode and the Connect button, then write `ui-review.json` containing that trial's exact `pid`, `window_id`, `mode: "Manual"`, `connect_xy: [x, y]`, `screenshot_sha256` and a review note. The PID/window IDs are in `run.json`; review cannot be reused across processes. Before clicking, the runner requests window-manager activation and verifies the owned window is both focused and under the pointer at the reviewed coordinates. A targeting mismatch stops before input. Only Connect is clicked. Handshake-arrival metadata and before/hover/after screenshots are recorded. Any nonzero feedback, changed reported position/encoder values, malformed motion data or unexpected child exit ends the attempt. The tool records these at the stock message's precision; it cannot establish sub-millimetre stationarity or source acquisition freshness.

Run under the already qualified X11/GPU and sourced ROS2 Humble environment, using the existing AVLite environment Python with Xlib/Pillow for the parent. Pass `--context`, `--player`, and a fresh `--results` directory. The bridge and observer child modes are invoked by the runner, not by default plugin loading. No outgoing/teleoperation node or autonomous-mode switch is started. Keep raw player logs private, review data/content hashes and geometry afterward, and retain incomplete/failed attempts. Actual connection, eight-topic delivery, first-frame scan/image conversion, guard termination and owned cleanup are verified in `neutral-authoring-activated`; neither required 60-second observation completed. The [SIM0-B06 report](../docs/stages/SIM0-linux-recovery-attempt.md) records the 1 mm position-step failure and its subsequently approved diagnostic proposal. The subsequent approved diagnostic uses an explicit profile described below; the default P0 guard remains unchanged.

This explicit analysis mode does not run inside the normal player/bridge path.

## SIM1-02 receiver guard

The guard is launched with `-roboracerGuard` and has a zero-output interlock unless `-roboracerMotionAuthorized` is given; the runner never passes that flag. The protocol is documented in [`PROTOCOL.md`](../integration/autodrive/sim1/PROTOCOL.md#roboracerguard1--receiver-guard-sim1-02).

`autodrive_neutral.py run --profile p0-creep --provenance --guard observe|scenario` adds the following to the neutral run:

- **Supervisor stand-in:** `autodrive_guard.py supervise`, run as its own OS process. It sends exact-zero requests at 20 Hz with a 1 s life to the bridge over a Linux abstract datagram socket.
- **Player launch:** the guarded player with `-roboracerGuardTrace <run>/guard`.
- **Acknowledgement checks:** a `GuardTracker` check of every frame's acknowledgements.
- **`observe`:** arms once and forwards every fresh request for `--duration`.
- **`scenario`:** scripts the disarmed P1a cases, each in its own arm epoch. It covers malformed, nonfinite and out-of-range content; duplicate and out-of-order requests; an expired original in a new envelope; envelope replay; lifetime, epoch and origin; arming faults; clock uncertainty and discontinuity; legacy and manual/GUI bypass; supervisor loss; and finally Devkit loss.

The parent performs the actions the bridge requests: killing or respawning the supervisor, a 1 s Up-arrow press plus a click on the reviewed driving-mode button, and killing the bridge. After the Devkit kill, it waits up to `--disconnect-wait` for the player's own trace to show lease expiry and disconnect. Guarded runs require the pre-Connect review to report mode `Guarded`; scenario runs also require it to report the driving-mode button's `mode_xy`. Legacy reply controls stay exact-zero except in the legacy-bypass probe, which sends finite in-range values the guarded player must ignore.

`analyze` adds a `guard` block: the authoritative `guard-trace.jsonl` analysis (no nonzero output/torque/steer step, every applied id accepted while armed and before expiry, expiry lateness, rejections by reason), the driver's phase results, and a cross-check that every event the driver relied on appears identically in the player trace. Tests are in `tests/test_autodrive_guard.py`. They compile and run the C# core cases (`integration/autodrive/sim1/tests/GuardCoreTests.cs`) under the pinned Editor's Mono, and run the full scenario driver against a simulated receiver, including a defective one.
