# S1 — 监督器骨架与完整的无运动命令路径

日期：**2026-10-05**。运行：`20261005T110210Z-s1-supervisor`。[英文报告](S1-supervisor.md)。计划：[修订 1.2](../planning/s1-first-amendment.md)，工作顺序第 3 步。下一步：[运动协议草案](../planning/s1-motion-protocol.zh-CN.md)。

**S1 监督器骨架通过，车辆未运动。** 已批准的命令架构现在由真实组件端到端运行：

AVLite `SyncExecuter` + `HoldController`（独立进程）→ 插件 `AutoDriveBridge` → **监督器**（独立进程，`roboracer.supervisor/1`）→ Devkit 桥接的守卫收件箱 → 仿真器内的接收端守卫。

在 60 秒互锁运行中，守卫接受的 233 个命令，每一个都能经由一条已转发的监督器请求追溯到一个 AVLite 请求。每个命令都是精确零值，保留原始生成时间，`deadline = 生成时间 + 500 ms`，并带有产生它的 AVLite tick 所用快照的身份。运行器存活租约在实际运行中生效：运行器在清理阶段停止心跳后，监督器在租约期内自行进入抑制状态。

**车辆未移动：** 守卫互锁开启，监督器运动闸门在代码中关闭，插件速度上限为 0。

## 1. 交付内容

| 部分 | 内容 |
| --- | --- |
| [`supervisor_core.py`](../../roboracer/runtime/supervisor_core.py) | 纯逻辑，见下文。 |
| [`supervisor_process.py`](../../roboracer/runtime/supervisor_process.py) | 以 `python -m roboracer.runtime.supervisor_process` 启动。用一个抽象数据报套接字接收请求和心跳，以非阻塞方式转发到守卫收件箱；接收端已满或不存在时计数。写入决策追踪（上限 64 MiB）和周期性状态文件，收到 SIGTERM/SIGINT 时退出码为 0。按 AVLite 加载器的要求，导入该模块不产生任何副作用。 |
| 桥接请求路径 | `connect(supervisor=...)` / `connect_supervisor()` 打开非阻塞套接字。每个不同的命令只发送一次，因此 AVLite 每个 tick 重新施加的保持命令只计数、不重发。每个请求携带其 tick 所用快照的身份（序号和采集时间戳）。 |
| tick 固定快照 | `SyncExecuter` 先调用 `get_sensor_frame()`，再单独调用 `get_ego_state()`。真值位姿现在与该 tick 的传感器帧来自同一快照，因此两次调用之间提交的新帧不会混入不同代的数据。 |
| 运行器 | `autodrive_neutral.py --plugin-stack` 用真实监督器替换替身，并在独立进程中以 10 Hz 运行 AVLite。运行器从主循环发送心跳，从 Connect 操作序列之后开始（该序列的输入处理会阻塞约 1 s）。 |
| [`autodrive_s1_supervisor.py`](../../scripts/autodrive_s1_supervisor.py) | 将 AVLite tick、监督器追踪和守卫追踪端到端关联比对。 |

**`supervisor_core.py`。** 按固定顺序检查每个请求，第一个失败项即为拒绝原因：
1. 格式错误；
2. 已抑制，或尚无运行器；
3. origin 错误、序号重复或乱序（即使后续检查失败，该序号也被消耗）；
4. 非有限值；
5. 请求生成时间在未来，或超过 500 ms 寿命；
6. 观测身份无效、观测超过 500 ms，或时间戳超前 100 ms 以上；
7. 超出速度或转向限制；
8. `motion-not-authorized`。

过期总是从请求的原始生成时间算起，转发不会刷新它。运行器存活租约为 500 ms，抑制状态不可自动解除。运动闸门在代码中无法打开：`Limits(motion_authorized=True)` 会报错。只转发精确零值，油门和转向为 `"0"`。

**对运动协议的发现。** 观测时龄的余量最紧：最大 489 ms，上限 500 ms。其组成：
- 采集到发出约 43 ms；
- 传输时间；
- 运行器 100 ms 的回复节拍（它推迟了 provenance 消息）；
- 等待下一帧，最多一个遥测周期（约 258 ms）。

3.9 Hz 的遥测也限制了闭环控制。[协议草案](../planning/s1-motion-protocol.zh-CN.md)提出了处理方案。

**分析修正（已保留）。** 第一次分析把观测结束后的 9 个 `inhibited` 决策判为失败（`s1-supervisor-analysis-v1-flagged.json`）。现在只在抑制来自观测结束之后的租约过期时才接受这些决策；观测期间的任何拒绝或状态变化仍判为失败。观测时龄现在只按已转发的请求统计。

## 3. 测试

插件测试共 26 个，其中新增 7 个：
- 核心转发保留原始生成时间；
- 运行器要求与不可自动解除的租约；
- 完整的检查顺序；
- 序号与 origin 规则；
- 运动不可被授权；
- 通过套接字测试真实进程（转发、运动闸门、格式错误输入、实时租约抑制、正常退出）；
- 桥接客户端（无观测、保持命令重发、tick 中途提交快照时仍固定身份）。

运行器、provenance、守卫和扫描检查测试套件均通过。无仿真器的离线冒烟运行显示栈和监督器以 10 Hz 运行，且退出码均为 0。该冒烟运行还发现 AVLite 的浮点时间累加使约 20 % 的 tick 跳过控制；现已把各阶段周期设为 tick 周期的 0.99 倍。
