# S1-02（第一部分）— 受保护播放器上的桥接观测路径

日期：**2026-10-05**。运行：`20261005T102231Z-s1-02-live`。[英文报告](S1-observation.md)。计划：[修订 1.2](../planning/s1-first-amendment.md)，工作顺序第 2 步。

**S1-02 的观测部分通过。** 插件的 `AutoDriveBridge` 现在订阅带来源信息（provenance）的 Devkit 话题，把每个遥测帧组装成一个经过校验的快照，并据此提供 AVLite `SensorFrame` 和带标签的真值位姿。

- **扫描检查：** LiDAR 的光束顺序、角度约定和安装位置已用构建场景的几何进行核对。
- **实时运行：** 在 SIM1-02 播放器上进行了 60 秒互锁运行。240 个带采集时间戳的帧，每帧都恰好生成一个快照；每个快照的扫描都是该帧自己的扫描，位姿都是该帧自己的 IPS/IMU 值。

**本部分不涵盖：** 对照仿真器实际响应核对命令符号和单位（S1-02 的另一半）。这需要车辆运动，因此须等数值运动协议确认（修订第 4 步）。**车辆未移动：** 零输出互锁始终开启，所有请求均为精确零，插件速度上限为 0。

**`SnapshotAssembler` 的检查。** 不同 ROS 话题之间没有相互顺序，因此组装器会先挂起每帧的 provenance 记录，再查找该帧的各个成员：
- LaserScan、IMU 和两个编码器：按精确的采集头时间戳匹配；
- 没有消息头的 IPS `Point`：按精确数值匹配。

出现以下任一情况时，该帧被拒绝并计数：
- 有成员被更新的时间戳证明缺失，或在 0.5 s 内未到达；
- 第一帧（时钟交换之前打的时间戳）；
- 会话变化、序号不递增或回合回退；
- 读数非有限值，或扫描布局与已鉴定布局不符；
- LiDAR 与 IPS 的采集时间相差超过 60 ms。

时间戳是主机 `CLOCK_MONOTONIC` 上的采集时间，与监督器请求属于同一时钟域。真值位姿标注为 `ground-truth`，并记录其 1 mm 的上报分辨率。

**坐标系与安装位置。** 车体原点是上报的 IPS 点，即后轴中心：序列化的 `Transforms/Rear Axle Center` 与其相差约 2 mm。它并不是 `Sensors/IPS` 物体，后者位于其前方 0.08 m 处。来自序列化 SIM1-02 场景的安装位置：
- LiDAR：(0.2733, 0, 0.096) m；
- IMU：(0.08, 0, 0.055) m；
- 轴距：0.331 m。

扫描共 1081 束，从 −135° 起逆时针，每步 0.25°，量程 0.06–10 m。

厂商强度值恒为 47，因此填充为 0。厂商 IMU 不含重力（静止时线加速度约为 0），姿态只上报 3 位小数。

## 2. 扫描约定、安装位置与光束顺序

将厂商模型的射线投射（`LIDAR.cs`：射线起点为 `Head.position`，Unity 中第一束为头部偏航角 + 135°，逆时针步进）与记录的扫描比较。位姿取自每帧的 IPS 位置和 IMU 偏航角。

在全部六个已记录的 SIM1-02 首帧中，该约定都是最佳假设：

| 假设 | 有限值不一致数 | 绝对误差 p50 / p95 | 5 mm 以内 |
| --- | --- | --- | --- |
| **自 −135° 逆时针，场景安装位置** | **1** | **2.0 / 8.8–9.2 mm** | **1035 束中 949–954** |
| LiDAR 位于后轴 | 3 | 28 / 71 mm | 279 |
| 安装位置镜像到后轴之后 | 5 | 53 / 147 mm | 78 |
| 光束顺序反转 | 53 | 189 / 385 mm | 19 |

残差与位姿量化一致：1 mm 和 0.001 rad，后者在 5 m 处约合 5 mm 的横向偏差。约 95 mm 的最大误差来自擦过边缘的光束。

**局限：** 六帧都位于同一出生位姿，未覆盖其他位姿。

**保留的失败。** 第一次比较无效，因为它完全没有预测到命中。其射线目标包含了车辆自身按场景位姿序列化的碰撞体，而 LiDAR 头部位于 Hokuyo 外壳碰撞体内部，因此每条双面射线都在 0.06 m 最小量程内击中外壳。Unity 的射线投射不会报告起点所在的碰撞体，所以这是工具缺陷，而不是扫描结果。现在只以静态场景为目标，并新增带封闭外壳的解析夹具防止回归。

## 3. 实时运行（互锁、未武装）

设置：一次全新进程试验，`--profile p0-creep --provenance --guard observe --plugin-observer`，60 s，SIM1-02 播放器。Connect 之前做了绑定 PID 和窗口的目视审查，画面显示：Guarded、Autonomous、油门 0.00 %、转向 0.00 rad、速度 0、编码器 [0, 0]、Disconnected。

**比对检查（全部 240 个采集帧）：**

| 检查 | 结果 |
| --- | --- |
| 快照 | 240/240，按遥测顺序。唯一的拒绝是第 1 帧（时钟交换前打的时间戳），其 5 条消息被丢弃。 |
| 扫描身份 | 240/240 个快照扫描与独立观察器消息的 ROS 时间戳和 float32 量程哈希相同。 |
| 真值位姿 | 240/240 等于原始 IPS 位置；240/240 的偏航角与原始 IMU 欧拉偏航角相差在 5 mrad 以内。 |
| 安装位置与标签 | 均符合规定，每个快照都标注 `ground-truth`。 |
| 扫描/位姿偏差 | p50 / p95 / 最大：24 / 47 / 50 ms，从未超过一个扫描周期。 |
| 时钟界 | 40–43 ms。 |
| 提交时的位姿时龄 | 196 / 210 / 219 ms。 |
| 桥接接收后的提交延迟 | 109 / 111 / 112 ms。 |

**延迟。** 延迟几乎全部来自运行器 0.1 s 的回复节拍：Devkit 桥接在节拍回复之后才发布 provenance 消息。若在回复之前发布 provenance，可减少约 100 ms，已记为 S1 延迟事项。

**现有运行器分析的标准检查：**
- 8 个话题各 241 条消息，约 3.9 Hz；
- 233 个零请求被接受并执行；
- 78,377 个守卫追踪步中 0 步非零输出，0 次拒绝，0 次过期；
- 最大上报位移 3 mm；
- 所有子进程退出码为 0 并已回收，端口 4567 已释放；
- 播放器 604 个文件在运行前后均未改变。

插件观察器约占单核 1.0 % CPU，常驻内存 112 MiB。

**保留的失败。** 第一次尝试丢失了 Connect 点击（与 SIM1-02 中相同）：窗口一直显示 Disconnected，有界的启动超时结束了这次尝试。五个子进程退出码均为 0，端口已释放。重试成功。证据：`observe-failed-connect/`。

- 在全新隔离的 AVLite 进程中检查桥接接口，包括真值门控、新对象，以及未调用 `connect()` 时不导入 ROS。

三个解析扫描检查夹具通过；运行器（12）、provenance（13）和守卫（10）测试套件不变且通过。

回放还发现了一个真实细节：Devkit 发布的 `angle_min` 是字面量 −2.35619 的 float32 值，与 −135° 相差 4.5 µrad。因此布局检查允许 1e-5 rad 的误差。
