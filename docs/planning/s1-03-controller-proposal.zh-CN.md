## 1. S1-03 必须交付的内容（计划原文，未改动）

> S1-03 — Deliver A through AVLite's actual execution path with visible GT labels, paced sampling and measured command-to-response behavior. Do not count executor ticks as physics steps.

计划还规定了以下规则：
- **转换在后端。** “测得的速度反馈、转换、饱和、速率限制和标定都放在后端执行层”，算法中不再保留第二个纵向 PID。
- **监督器在反馈过期时停车。** 若需要速度反馈控制器，监督器“在反馈过期时也要停车”。
- **A 是反应式的。** A 是“小型反应式集成基线：反应式转向，不做参考路径/走廊规划”。
- **AVLite 速度** 来自“已批准的带时间戳运动观测”，不得假定使用真值。

**推论：**
1. 速度环最多以 5 Hz 更新，总延迟约 0.3–0.45 s（采集 → 决策 → 转发 → 施加）。
2. 零油门即硬制动，因此控制器只能驱动或硬制动，无法滑行。
3. 闭环之前必须先测出油门到速度的稳态关系。

## 3. 需要的决定

**D4 — 速度环的反馈来源**（按计划，速度环本身在监督器中）。
- **（推荐）A：监督器自行订阅。** 它通过同一个 `SnapshotAssembler`，在私有 rclpy 上下文中读取编码器、IPS 和 provenance 话题，并用编码器角度和采集时间戳计算速度。这样监督器的输入不依赖算法进程是否正确，“反馈过期 → 停车”也按监督器自己的时钟判断。代价：监督器进程需要引入 rclpy。
- **B：桥接随每个请求发送实测速度。** 更简单，但反馈要经过算法进程。算法侧的缺陷可能给速度环喂错误的速度；不过算法挂起时，过期机制仍会让车停下。

**D5 — 后端速度控制器（v0.2 在 M3 后修订）。** 位于监督器中，只用于 AVLite 的 `request`；标定阶段不变。

**实测对象（M3）：**
- v_ss = K·u，K = 每单位油门 4.90 m/s（0.005–0.02 范围内为 4.89–4.91）；
- 一帧内稳定（≤ 0.23 s）；
- 请求生成到施加约 0.13 s，另有 0.2 s 帧量化；
- 零油门即硬制动，约一帧内停下。

**控制律（每个转发帧）：**
- `u = clamp(v*/K + u_I, 0, u_max)`，即静态逆前馈加有界积分修正。
  - `u_I ← clamp(u_I + Ki·e·Δt, −0.01, +0.01)`，其中 `e = v* − v`，`v` 是 D4 给出的编码器速度，Δt 是编码器采集的仿真时间间隔。
  - u 饱和时冻结 `u_I`；v* = 0 时将其清零。
- **没有比例项**：前馈已是对象的逆，积分修正只用于校正模型误差（±0.01 ≈ ±0.05 m/s）。
- **Ki = 0.10**（每 m/s 每 s），积分环穿越频率 K·Ki ≈ 0.49 rad/s。总延迟约 0.45 s 时，相位裕度约 90° − 0.49 × 0.45 rad ≈ **77°**。
- **u_max = 0.07**（约 0.34 m/s），足以在留有修正余量的情况下达到 v* = 0.3 m/s。
- **速率限制：** u 每帧最多上升 0.02（约每帧 0.1 m/s）；下降不受限制。
- **目标为 0：** u = 0（硬制动），积分修正清零。
- **超速（不变）：** v > v* + 0.15 m/s，或 v > 0.5 m/s → 该帧 u = 0。
- **反馈过期（不变）：** 反馈超过 0.4 s 或缺失 → u = 0；超过 0.6 s → 解除武装。
- **重新整定：** M4 只能在 M3/M3b 测得值的 ±50 % 内调整 Ki、±10 % 内调整 K，每次修改都有记录。

**适用范围：** K 只测到 0.1 m/s（u = 0.02）。M4 使用之前，必须由 M3b（D8）确认到约 0.3 m/s（u ≈ 0.06）。
- **转向：** 精确换算 `normalized = clamp(steer_rad / 0.5236, −1, 1)`，不另加速率限制（厂商以 183°/s 转动）。只有 D8 授权行驶中转向时才转发转向；在此之前任何非零转向都被拒绝。

**D6 — 反应式基线 A，作为 AVLite 插件 `ControlStrategy`（`GapFollowController`）。**
- **转向：** 基于车体坐标系 LiDAR 的 follow-the-gap 加 disparity extension（扫描取自 `SensorFrame`，已应用安装位置）。
  - 忽略 ±100° 之外的光束。
  - 障碍物膨胀半车宽（0.15 m）+ 0.10 m 余量。
  - 朝最深的自由方向转向，steer = atan(2·L·sin α / l_d)（L = 0.324 m，l_d = 1.0 m），限幅 ±0.35 rad。
- **目标速度：** `v* = min(0.3, 0.3 · (1 − |steer| / 0.6), 0.25 · (d_front − 0.5))`，下限为 0，其中 `d_front` 为 ±10° 内的最小距离。从不使用真值位姿。
- **输出：** `TargetSpeedSteeringCommand`。真值位姿只用于带标签的日志和进度。
- **AVLite 状态：** 桥接用编码器速度填写 `EgoState.velocity`，标注为 `encoder`，使 AVLite 状态有已批准的速度来源。不使用真值速度。

**D7 — 节拍采样与命令到响应的测量。**
- AVLite 按挂钟 10 Hz 运行；各阶段周期为 tick 周期的 0.99 倍（与现在相同）。
- 物理进度使用 provenance 中的仿真时间（仿真时间与固定步），绝不使用 tick 计数。
- 对每个转发的请求记录如下链路：
  - AVLite tick 开始 → 请求生成 → 监督器决策 → 守卫接受（仿真时间）→ 首个施加步；
  - 然后是首个观测到的响应：油门为编码器速度变化 > 0.01 m/s，转向为车轮角达到目标的 90 %。
- 各段延迟分别报告，绝不跨不相关的时钟相加。

**D8 — 下一批运动阶段。** 每个阶段单独确认、单独运行，除下文另有修改外，适用运动协议 §3 的全部规则。
- **M3 辨识（开环、直线、转向 0）。** 标定源分别保持油门 0.005、0.01 和 0.02。每次保持到编码器速度 ≥ 0.3 m/s、达到 2.0 s 或行驶 0.5 m 为止，然后回零。每次都从静止开始。最多 6 次试验，每次从出生点的全新进程开始。测量油门对应的稳态速度（若达到）、加速度随速度的变化，以及从 0.3 m/s 起的制动距离。由此得到 `u_ff` 并确认 b。
- **M3 结果（v0.2）：** 已通过。v ≈ 4.90 m/s × 油门，一帧内稳定，在 0.005–0.02 范围内线性。
- **M3b（v0.2 新增）：在 M4 速度范围内辨识（开环、直线、转向 0）。** 标定源、规则与结束条件都与 M3 相同（编码器速度 ≥ 0.3 m/s、2.0 s 或行驶 0.4 m，然后零油门），保持段油门为 **0.03、0.045、0.06**，预计速度约 0.15、0.22、0.29 m/s。
  - **通过条件：** M3 的标准，另加每个油门档的 K 都在 4.90 的 ±10 % 以内（否则用实测映射替代 D5 中的单一增益）。
  - **每个保持段预计：** 最多约 0.4 m 行驶，加上约 0.19 s × 速度的制动距离（≤ 60 mm），因此每次试验约 1.4 m。正前方 7.4 m 的直道足够。
  - **试验：** 最多 6 次。
- **M4 闭环速度（直线、转向 0、D5 生效）。** AVLite 运行一个测试控制器，依次请求 v* = 0.1、0.2、0.3 m/s，各持续 3 s，然后为 0。每次试验行驶不超过 2.5 m。通过条件：
  - 每一步最后 1 s 的平均速度与 v* 相差在 ±0.05 m/s 以内；
  - 超调 ≤ 0.1 m/s，无油门/制动抖振（每步最多 2 次制动）；
  - 从 0.3 m/s 起 1.5 s 内停车；
  - 注入反馈过期（扣住编码器话题）→ 0.4 s 加一帧内 u = 0。
- **M5 A 在赛道段上运行（行驶中转向）。** `GapFollowController` 从出生点出发，最多行驶 6 m 或 40 s，v* ≤ 0.3 m/s，然后运行器请求 0 并解除武装。这是 S1-03 的演示及其命令到响应测量。新增中止规则：
  - 侧向余量 < 0.15 m；
  - 前向余量（±10°）< 0.5 m；
  - 速度 > 0.5 m/s；
  - 请求的 |steer| > 0.35 rad；
  - 连续 2 帧没有快照。
- **本方案不包括：** 完整跑圈（M1 赛道回合、S1-05/06）、超过 0.3 m/s 的速度、倒车。
