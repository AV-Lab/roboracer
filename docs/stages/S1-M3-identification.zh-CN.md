# S1-03 阶段 M3 — 开环油门辨识

日期：**2026-10-05**。运行：`20261005T123651Z-m3`。[英文报告](S1-M3-identification.md)。方案：[s1-03-controller-proposal.md v0.1](../planning/s1-03-controller-proposal.zh-CN.md)，D8。批准：“approve D4 A, D5, D6, D7; run M3 only”（[记录](../planning/s1-motion-approval.json)）。

**M3 通过，并改变了对象模型。** 持续油门并不会让车辆持续加速。在一个遥测帧内（≤ 0.23 s），速度就稳定在与油门成正比的稳态值：

**v ≈ 4.90 m/s × 油门**，在 0.005–0.02（0.025–0.10 m/s）范围内线性度优于 0.5 %。

零油门约在一帧内使车辆停下，制动距离约为 0.19 s × 速度。已批准的 D5 数值基于纯加速器模型推导，且 **u_max = 0.03 会把速度上限限制在约 0.15 m/s**。现提出修订版 D5（方案 v0.2）和一个简短的 M3b（验证到 0.3 m/s 的线性度），等待确认。M4、M5 未获授权。

## 1. 设置

- **阶段 `m3`。** 油门 {0, 0.005, 0.01, 0.02}，转向恰为 0。只有提供批准记录和 SIM1-03（D1）构建记录时才会开启。
- **保持段。** 标定源每帧发送当前保持段的油门（按帧对齐）。每个保持段在编码器速度 ≥ 0.3 m/s、达到 2.0 s 或编码器行驶 0.4 m 时结束，随后零油门制动。下一个保持段必须从静止开始，且至少间隔 1.5 s。
- **速度测量。** 两个车轮编码器角度的平均值 × 0.059 m，按编码器采集的仿真时间计算。M1 已确认编码器 `JointState` 的 position 即车轮转角（rad）。
- **安全规则。** §3 的规则全部适用：预检查、中止监控、18 s 武装上限、2 m 桥接包络。

从油门开始后的第一帧直到油门结束，速度曲线都是平的。第一帧就已达到稳态速度的 99–100 %，因此稳定时间只能以帧周期为上界，无法分辨得更细。

- **扭矩：** 每个保持段中每轮扭矩恰为 85.6 × 油门 / 4。之后直到下一个保持段，全部电机扭矩为 0，制动为 85.6 N·m（D1）。
- **路径：** 横向偏离 ≤ 1 mm，航向变化 0.0°，向前行驶。编码器行驶（51.6 / 102.7 / 205.4 mm）与 IPS 行驶（51 / 103 / 205 mm）相差在 0.6 mm 以内。
- **命令路径与进程：**
  - 78 个请求全部转发；
  - 守卫检查通过：武装、无拒绝、无 fault、恰好一次零输出下的最终 `lease-expired`、解除武装；
  - 45,188 个追踪步；
  - 试验在 54 s 内自行结束，所有子进程退出码为 0，端口已释放，播放器 604 个文件均未改变。
- **重新解读 M1：** M1 中“0.2 s 脉冲每单位油门峰值约 4.7 m/s”其实就是这个稳态增益（在脉冲内即已达到）。由此推导出的“加速度”是帧量化造成的假象。

**分析修正（已保留）。** 第一次分析中，每个保持段之后 2.5 s 的窗口与下一个保持段重叠（下一个保持段约 1.5 s 后开始），导致保持段 0 和 1 的停车、制动和峰值检查失效（`m3-trial4-analysis-v1-flagged.json`）。现在窗口截止于下一个保持段。制动从油门结束前的最后一帧起算。无意义的“初始加速度”指标已改为稳态增益和稳定时间上界。

## 4. 影响与下一步

- **D5 必须重新推导。** 对象是带短滞后的静态增益（K ≈ 每单位油门 4.9 m/s，一帧内稳定），另有约 0.13 s 的请求生成到施加时间和 0.2 s 的帧量化。[方案 v0.2](../planning/s1-03-controller-proposal.zh-CN.md) 修订了 D5：
  - 前馈 u = v*/K，加一个小而有界的积分修正；
  - u_max = 0.07（约 0.34 m/s）；
  - 每帧上升不超过 0.02；
  - 过期反馈与超速规则不变。

  同时提出 **M3b**：在 0.03、0.045、0.06 处做保持，在 M4 之前确认到约 0.3 m/s 的线性度。
- **无人值守运行：** 保持桌面解锁。现在 `idle-delay` 为 0，但 `lock-enabled` 仍为 true，手动锁屏或挂起后锁屏仍会再次阻断运行。由于窗口级截图看不到锁屏，在 Connect 之前做一次根窗口锁屏检查是一个低成本的后续改进。
