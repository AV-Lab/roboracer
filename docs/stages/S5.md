## 4. S5-04 GUI and settings check (D74) — visibility shown; settings round trip shown; one GUI finding (D76)

**Evidence:** `artifacts/s5/20261101T165935Z-gui-settings/`. Everything ran in the **fresh environment** with its **isolated** AVLite config directory; nothing outside it was changed.

**Isolated profile.** It was written with AVLite's own `save_setting` (`make_profile.py`) and passes `avlite setting-cli validate`. It:
- registers the plugin (`c62_community_plugins: roboracer`);
- selects the S4 stack;
- sets the committed V1 plan as the default global trajectory.

**Visibility in AVLite's standard visualizer** (`visualizer-1-crop.png`). Our classes are shown in the stock dropdowns:
- Perception `PerceptionPipeline`, with Detect `ScanObstacleDetection`;
- Localization `MapIcpLocalization`;
- Global planner `RaceLineGlobalPlanner`, with its default global plan;
- Controller `RacingLineController`;
- Bridge `AutoDriveBridge`, with world capabilities LIDAR_2D and IMU and stack capability LOCALIZATION.

**GUI finding (D76).**
- **What happens.** The visualizer showed **"Startup failed: This method should be implemented by the simulator or ROS bridge."** Its plot view calls `world.get_ground_truth_perception_model()`, which `AutoDriveBridge` does not implement (AVLite's base raises `NotImplementedError`).
- **Why the method is missing.** That is deliberate truth isolation: the S3/S4 proofs ran through `executer.step` and never called it.
- **What follows.** Starting a live run from the visualizer is not supported today. The stage runner and `scripts/roboracer.py live` are the supported launch paths.

**Settings edit, save and reload** (`settings_roundtrip.py`), with AVLite's own `save_setting` / `load_setting` (the settings window's code path):
- the plugin is loaded by AVLite's loader;
- its `PluginSettings` are saved into the isolated profile;
- `request_life_ms` is edited from 500 to 450 and saved;
- a **new process** loads 450;
- the profile holds `plugins: roboracer: request_life_ms: 450.0`.

**Not done: interactive editing in the settings window.** Desktop `:1` is the user's live working session (Emacs and this terminal were on screen), and the synthetic clicks did not reach AVLite's Tk dialog. I closed the visualizer instead of continuing to click on the live desktop.

**Validation:**
- **The plugin schema protects the plugin:** a profile copy with a non-loopback `autodrive_host` (8.8.8.8) loads with the safe value kept, so the plugin's validator rejected the field.
- **Limitation (AVLite):** `setting-cli validate` reports that same profile as valid. It does not check plugin sections.

**D76 — proposed:**
- **A (recommended): do not implement it.** Document the visualizer as supported for configuration and profile editing, and the stage runner / entrypoint for live runs. Truth isolation stays as proven.
- **B: implement `get_ground_truth_perception_model()` for visualization only.** It would return the labelled IPS ego with no obstacles. This needs a guard that the stack never calls it on ICP stages, and a re-run of the S3/S4 truth-isolation proofs.

- **No contact.** Heading error at most 0.125 rad.
- **What it shows:** a box placed where the track narrows is not handled by the C0 lattice settings, and in that situation the blocked-stop distance is not guaranteed. It is a limitation of the S4 stack that the S4 fixtures did not reveal.
- **D69 still applies:** no algorithm change before the held-out evaluation.

**D77 — H2 (decision needed):**

   - **Fix:** runner launches keep the sourced ROS environment, as in all S1–S4 runs.
