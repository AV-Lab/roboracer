# S1 运动阶段 M2 — 运动中的停车：算法挂起与运行器丢失

日期：**2026-10-05**。运行：`20261005T122018Z-m2`。[英文报告](S1-M2-stops.md)。协议：[s1-motion-protocol.md v0.1](../planning/s1-motion-protocol.zh-CN.md) §3–§4。批准：“yes run M2”（[记录](../planning/s1-motion-approval.json)）。

**M2 两个用例均通过。** 车辆以油门 0.01、转向 0 行驶。在每个用例中，车辆都只靠独立机制停下；从未发送零命令来让它停车：

- **(a) 算法挂起。** 请求源发出一个 0.01 请求后停止发送。守卫租约在该请求生成后 500 ms、油门仍在施加时过期。从那一步起，全部电机扭矩为 0 且制动施加，车辆在请求生成后 **0.78 s** 停下。
- **(b) 运行器丢失。** 运行器停止心跳，而请求源继续每帧请求 0.01。监督器恰在其 500 ms 运行器租约到期时自行抑制，并拒绝之后的全部请求（12/12 为 `inhibited`）。随后守卫租约在油门仍施加时过期，车辆在最后一个已转发请求生成后 **0.76 s** 停下。

这就是 F1/S1-04 中的“过期请求”和“运行器退出/挂起”用例，现已**在运动状态下**得到验证。

## 1. 设置

- **阶段 `m2`：** 油门 {0, 0.01}，转向恰为 0。只有提供批准记录和 SIM1-03（D1）构建记录时才会开启。
- **每个用例：** 各一次全新进程试验（每次都以不可自动解除的守卫停车结束），并做 Connect 前的目视审查。§3 的共同规则均适用：出生位置与余量预检查（前向 2.26 m，两侧 0.74 / 0.54 m，静止）、中止监控、18 s 武装上限、桥接 2 m 包络。
- **用例 (a)：** 静置 3 s 后，标定源按遥测帧对齐发送一个 0.01 请求，之后不再发送。
- **用例 (b)：** 标定源写入暂停请求，运行器主循环读到后不再发送心跳。标定源在 3 s 内每帧请求 0.01，然后停止。必须由监督器的 500 ms 运行器租约将其切断。
- **停车方式：** 两个用例中标定源都不发送零命令来停车。中止时它只能停止发送；本次未发生中止。

| 油门施加时长（守卫） | 0.368 s | 0.768 s |
| 每轮扭矩 | 0.214 N·m（= 85.6 × 0.01 / 4） | 0.214 N·m |

| 横向 / 航向变化 | 1 mm / 0.0° | 1 mm / 0.0° |

**用例 (b) 中监督器的时序。**
- 运行器心跳平均间隔 117 ms（共 38 次）。
- 监督器在运行器*读到*暂停请求后 0.405 s 进入抑制。这意味着它收到的最后一次心跳比读到暂停早 95 ms，在一个心跳间隔之内。因此租约恰在最后一次心跳之后 500 ms 触发。
- **分析修正（已保留）：** 我最初的检查以读到暂停的时刻为基准，要求 0.5–0.7 s，因而把这一正确行为判为失败（`m2-b-analysis-v1-flagged.json`）。修正后的检查要求：抑制不晚于读到暂停后 0.5 s 加 20 ms 节拍，且不早于 0.5 s 减去 1.5 个心跳间隔。

**为什么用例 (b) 的油门施加更久。** 监督器会一直转发到其租约过期（最后一次心跳后最多 0.5 s），守卫随后还会执行最后一个已转发请求，直到其自身租约结束（生成后 0.5 s）。因此运行器丢失后，最坏情况下的施加时长约为一个心跳间隔 + 0.5 s + 0.5 s。本次为 0.77 s，停车仍以很大余量满足协议界限。

**进程与播放器：** 两次试验都自行结束（49 s 和 48 s），所有子进程退出码为 0。端口已释放，播放器 604 个文件均未改变。
