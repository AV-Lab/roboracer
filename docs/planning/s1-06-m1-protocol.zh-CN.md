# S1-06 — M1 运行协议（F1 故障矩阵与计时窗口）— 待确认方案

版本 **0.1**，2026-10-06。[英文版](s1-06-m1-protocol.md)。计划条目 S1-06：*运行 M1，保留失败记录，并按冻结的 S1 运行限制发布首批时序/资源/回合测量；在 S2 验收前提出后续性能预算供审查。* 运行矩阵对 M1 的定义是：C0；A；真值带标签；三次独立的受限跑圈运行；每个 F1 案例三次；按采样协议的五个计时窗口；时长、边界和容差须在运行前冻结。**在你确认之前，本文内容均不会运行。**

## 1. 已有测量（无新运动）

`scripts/roboracer_timing.py` 按计划的采样窗口测量了三次 M6 跑圈：run 阶段开始后 10 s 预热，然后 120 s。数据见 [S1-06 报告](../stages/S1-06-measurements.zh-CN.md)。所有冻结的 S1 限制都有余量地满足：
- 请求时观测年龄：最大 334 ms（限制 500）；
- 遥测间隔：最大 248 ms（限制 500）；
- 时钟界：最大 42 ms（限制 400）；
- 最终停车：最长 0.32 s（限制 1.5）。

这三个窗口在运行前未声明为计时运行，因此按初步数据报告。GPU 使用情况当时未采样；运行器现在每秒从独立线程采样一次。

## 2. 需要的决定

**D12 — 跑圈演示。**
- **（推荐）** 将三次 M6 跑圈（2026-10-06，全部干净，独立评分，在已确认的 M6 边界内运行）计为 M1 的三次独立受限跑圈运行。
- 另一选择是再跑三次 M6。

**D13 — 五个计时窗口。** 五个全新进程的 M6 跑圈回合，与 M6 完全相同（A-lap、相同限制、框式围栏、33 m 或 200 s 结束），并开启 GPU 采样。
- 窗口：run 阶段开始后 10 s 预热，然后 120 s。一圈的 run 阶段约 139 s，窗口放得下。
- 停止规则与 M6 相同：第一次出现中止、接触或出界即停止并报告。
- 这些是计时运行。如果你希望它们同时算作额外的跑圈证据，请说明；默认单独报告。

**D14 — F1 故障矩阵**，见下文。共九个案例，每个在全新进程中运行 3 次：共 27 个短回合。

**D15 — 行驶中故障的停车边界。** 协议原有的停车判定（最后一个非零请求后 1.5 s 内停车且行驶不超过 0.15 m）是为 M1–M3 脉冲（油门 ≤ 0.06）制定的。在 M6 的 0.3 m/s 下，设计上最不利的路径是运行器挂起：监督器继续转发，直到 0.5 s 运行器租约到期；之后守卫还会执行最后一个请求，最长 0.5 s。仅这一段就可能在制动前行驶 1.0 s × 0.3 m/s = 0.30 m，而制动本身约需一帧。
- **（推荐）** 对 F1 案例：注入后 **1.5 s** 内停车（速度 < 0.02 m/s，时间限制不变），注入后行驶距离 **≤ 0.40 m**；同时独立评分器判定无接触、无出界。
- 这是为新工况新增的边界，不修改任何先前阶段的判据。

**D16 — 运行器出错时的清理顺序（代码修改）。** 目前运行器出现异常时会直接终止其拥有的进程，因此永远观测不到停车：杀掉播放器只算围堵，不算制动。
- **（推荐）** 出错时，运行器先发送守卫解除武装并停止心跳；然后最多等待 2 s，直到守卫报告 `disarmed` 且编码器速度归零，记录结果，之后才终止子进程。

## 3. F1 案例（每个 ×3）

**所有案例共同的部分：**
- **起始：** 一个 M6 回合（全新播放器在出生点启动，Connect 前目视检查，A-lap，M6 限制）。
- **注入：** 由栈阶段在 run 时间 **6.0 s** 时注入。此时车辆约以 0.3 m/s 行驶在起始直道上，离出生点约 1.5 m；M5 和 M6 表明该处前方净空 ≥ 1.3 m。
- **结束：** 注入后 **8 s** 结束回合；若案例本身会结束进程，则更早结束。
- **每个案例都必须表明：**
  - 预期的检测；
  - 检测截止时间之后没有施加任何非零命令；
  - 满足 D15 停车边界；
  - 无守卫故障，除非案例列出；
  - 无接触、无出界；
  - 所有进程已回收，播放器未改变。

| # | 案例 | 注入方式 | 预期检测与结局（冻结） |
| --- | --- | --- | --- |
| F1-1 | 扫描缺失 | 测试钩子冻结 LiDAR 采集 5 s（播放器以 `-roboracerTestHooks` 启动，与 SIM1-01 相同）；桥接在栈触发时转发冻结请求 | 1 帧内快照因 `scan/pose skew` 被拒绝。最后一个有效快照后 ≤ 0.5 s，栈以“无新观测”中止并请求零速。监督器拒绝观测年龄超过 500 ms 的请求（`stale-observation`）。按 D15 停车。 |
| F1-2 | 扫描无效 | 栈的桥接把接收到的扫描距离替换为 NaN，持续 5 s（`AutoDriveBridge` 中仅供测试的钩子，默认关闭） | 快照因 `non-finite reading` 被拒绝；之后结局同 F1-1。 |
| F1-3 | 请求过期（算法挂起） | 栈停止推进 AVLite（进程仍在，不再发请求） | 守卫租约在最后一次生成后 ≤ 0.5 s 到期（`state stopped lease-expired`）。按 D15 停车。 |
| F1-4 | 非有限请求 | (a) 控制器返回 NaN 目标速度；(b) 另向监督器套接字直接发送一个 NaN 请求，绕过插件 | (a) 插件拒绝（`target_speed is not a finite number`），不发送任何内容。(b) 监督器以 `non-finite` 拒绝。非有限值不会到达守卫；租约到期；按 D15 停车。 |
| F1-5 | 解除武装 / 重新武装 | 运行器发送守卫解除武装；静止 3 s 后重新武装（新 epoch），栈恢复行驶 3 s，然后请求零速 | 守卫 `disarm-request`，然后按 D15 停车。解除武装期间：输出为零，请求以 `not-armed` 被拒绝。旧 epoch 的请求以 `stale-epoch` 被拒绝。重新武装后，新请求被接受，车辆再次行驶。最终一次租约到期。 |
| F1-6 | 算法退出 | 运行器对 AVLite 栈进程发送 SIGKILL（标记为预期的终止） | 不再有请求到达；守卫租约在最后一次生成后 ≤ 0.5 s 到期；按 D15 停车。运行器记录该退出，并继续观测直到案例结束。 |
| F1-7 | 运行器挂起 | 运行器停止心跳（M2 的机制），但进程保持存活 | 监督器在 0.5 s 运行器租约到期时抑制（`runner-lease-expired`），并拒绝之后的请求；守卫租约到期；按 D15 停车。 |
| F1-8 | 运行器退出 | 回合封装器对运行器进程发送 SIGKILL | 监督器经运行器租约抑制；守卫租约到期；按 D15 停车，可在守卫跟踪和播放器的遥测日志中看到。之后封装器按记录的进程组回收遗留的子进程。 |
| F1-9 | 运行器出错 | 在运行器主循环中抛出异常 | 按 D16 顺序：解除武装，在 D15 边界内观测到停车，然后清理。运行记录该错误，并保留在证据中。 |

**保留：** 失败、中止和超时的尝试都会保留并报告。按照 D11，某个案例一旦出现意外结局，我就停止该案例，并在重复前先报告。

## 4. 运行前需要构建的内容（无运动）

- **故障触发：** 栈阶段在注入时间写出 `fault-inject.json`；桥接、运行器和控制器的钩子据此动作。所有钩子默认关闭，只有选择了某个案例才启用，而案例只能通过命令行（`--f1-case`）选择。
- **钩子：** `AutoDriveBridge` 中仅供测试的扫描损坏和控制器 NaN 输出，D16 清理顺序，以及封装器的运行器终止与遗留进程回收。每项都有单元测试，并在无仿真器的条件下做离线冒烟运行。
- **分析：** `roboracer_f1.py` 根据跟踪记录检查每个案例的冻结预期结局；`roboracer_timing.py` 负责计时窗口。
