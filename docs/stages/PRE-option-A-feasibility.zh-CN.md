## 2. 构建可行性与风险

官方仍提供该编辑器及 Linux 模块的下载入口。不过 Unity 2021.3 的官方 Linux 编辑器要求列出 Ubuntu 18.04／20.04 和 CentOS 7，未列出本机 Ubuntu 22.04。因此需要实际验证，不能把“现有播放器能运行”推导为“本机编辑器能够可靠构建”。建议先在独立目录验证精确旧版；若因系统兼容性失败，保留日志，再比较另一台已获授权的构建主机与升级引擎的成本。不能自动更换系统、升级 Unity，或把容器称为官方支持的解决方式。[版本页](https://unity.com/releases/editor/whats-new/2021.3.9f1)、[2021.3 系统要求](https://docs.unity3d.com/2021.3/Documentation/Manual/system-requirements.html)。

项目使用 IL2CPP standalone 后端，但包配置选择 Windows 到 Linux 的交叉工具链。已确认 `com.unity.toolchain.linux-x86_64@2.0.4` 存在，并依赖同版本的固定 sysroot 组合。修订案建议允许在新副本中进行明确记录的构建依赖适配，不升级其他包或改动物理参数；最终仍以实际依赖解析和编译为准。[Linux IL2CPP 文档](https://docs.unity3d.com/2021.3/Documentation/Manual/linux-IL2CPPcrosscompiler.html)。

当前官方支持用户目录中的 Hub AppImage，并说明 FUSE3 及解压运行路径；不必先增加全局 apt 仓库。编辑器和 Linux IL2CPP 模块单独锁定版本，Hub 的实际版本也应记录。账号与适用许可由你自行选择、激活；本任务不包括购买许可或由 agent 处理凭据。已提出的环境问题仅询问采用本机 Hub、已有授权构建环境，还是尚未确定，不需要密码、许可证文件或密钥。当前 Hub／许可文档不保证旧版编辑器兼容，仍需实测。[Hub 安装](https://docs.unity.com/en-us/hub/install-hub-linux)、[激活说明](https://docs.unity.com/en-us/engine/6000.5/manual/get-started/install-and-upgrade/licenses-and-activation/managing-your-unity-license)。

源码包含 Robotec 原生库调用和多个第三方资源目录；检查的 F1TENTH 场景使用项目自己的射线 LiDAR。最初应保留依赖闭包，不因目录看似无用便删除，以免造成编译或引用失败。根许可证为 BSD-2-Clause，部分供应商资源附有其他条款。应保留声明，在未来确定发布内容前，不把整个模拟器工程或产物随插件推送；私有仓库也不能证明所有资源适用同一许可证。这里记录的是实际包装约束，不作法律结论。[固定源码](https://github.com/Tinker-Twins/AutoDRIVE/tree/635dbb6d86ec98e25ea845a97188f7bbe85a09e8)、[声明检查记录](../../artifacts/preflight/20260929T051932Z/third-party-notice-inspection.json)。

## 3. 拟增加接口的代码位置与边界

以下为**设计建议**，不是已经存在或实现的 AutoDRIVE API。

| 源码位置 | 当前行为 | 拟进行的限定修改 |
| --- | --- | --- |
| `Socket.cs` 与 Socket.IO 组件 | 遥测依赖 Bridge 回复链；断开主要改变 UI；事件在 `Update` 中处理，缺少采集身份、接收端租约和已应用指令确认。 | 增加版本／能力握手、受限队列与独立遥测调度；验证模式禁用旧式执行器写入旁路。不能靠发送运动指令来维持遥测。 |
| `LIDAR.cs`、`WheelEncoder.cs`、`IMU.cs`、`IPS.cs` | 物理回调更新后保留最新数据，没有采集身份；图像在序列化时采集。 | 在真实采集完成位置记录 episode、source、序号、仿真时间和接收端单调时间；发布不可变样本，并分别保留各传感器时刻。重复发布不得刷新采集时间。基线比较保留原相机负载。 |
| `VehicleController.cs` | `FixedUpdate` 依次获取输入、转向、驱动；源码中零驱动扭矩会选择制动；Inspector 范围注解不是运行时校验。 | 在实际执行前直接检查权限与过期，拒绝非有限值、越界、旧 episode／指令；失败进入锁定停止／故障状态。先验证制动路径确实应用，再申请有限运动实验。 |
| `SceneReset.cs` 与模式／场景状态 | GUI 复位重载场景，缺少已验证的外部事务。 | 加入解除执行、失效旧 epoch、复位／初始化、等待新数据、显式重新启用的流程。S1 可先使用已核实的单一起点；无人值守与五起点仍在相应后续阶段验证。 |
| `LapTimer.cs`、碰撞体与变换 | GUI 圈数逻辑和已舍入遥测不足以作为独立评分依据。 | 给评测器提供真值、几何、接触信息，并独立验证 C0 进度及完整车身越界判定；与驾驶可见观测隔离。 |

接收端保护**补充独立监督进程**。整个模拟器主线程冻结时，它也无法执行制动；此时必须标记失败并限制该仿真会话，不能声称已经停车。线程恢复后，必须先拒绝过期授权，再允许下一次执行。

C# 与 Python 单调时钟也不能默认同源。协议须保留原始指令生成时间／截止时间，实测跨进程时钟转换误差，并增加接收端最大租约。重复转发不能延长旧指令寿命；时钟界限或真实采集新鲜度不合格时，保持禁止运动。

编码器实现使用硬编码 `0.065` 轮径及固定 tick 距离因子，而上一轮安装对象检查得到 WheelCollider 半径 `0.059 m`。因此不能直接接受现成便利速度字段。建议使用带时间戳的原始计数及明确验证的轮径、分辨率、符号，并在获准的运动实验中与仅供评测的真值速度比较；轮滑仍是剩余风险。这不意味着重调物理模型，也不允许把真值速度暗中输入后续 ICP 驾驶状态。

## 4. 推荐修订及保留范围

[英文修订案](../planning/simulator-build-amendment.md)提出两个可演示阶段：

1. **SIM0：原版源码构建。** 完成资源获取、用户许可激活、固定工具链和一次干净构建；随后进行两次独立启动，每次在首个完整数据帧后观察 60 秒，全程保持零执行器回复。验收需要真实传感器、Humble／AVLite 接收和进程清理，不能仅以编译成功通过。
2. **SIM1：可观测、受保护的验证后端。** 增加真实采集时序、接收端过期、生命周期和最低评分输入；先进行禁止运动的接口／故障验证，再提交数值运动协议。获得协议批准后才进行限定的控制与停车实验，以完成 PRE-03／04。

每阶段结束提交报告并停止，等待下一阶段确认。修订案新增 **10 个未勾选 todo**，与原批准的 34 项分开；没有减少原有验收次数或降低通过条件。本次建议批准修订案并**仅进入 SIM0**。

S1–S5 的功能目标、M1–M5 验收矩阵不变。Humble、插件内 ICP 扩展、Pure Pursuit、目标车速／转角与独立进程监督保持已确认路线。S2 负责无人值守客户端及复位控制；S3 验证五种初始位姿；S4 增加限定静态障碍配置及几何验证。不为第一次闭环提前实现所有后续场景功能。通用场景编辑、动力学改进、另一模拟器、多车和自动全局定位恢复均未纳入当前扩展。

新增成本是 Unity 工具链、维护上游补丁、导入／构建耗时及模拟器接口测试。收益是获得可检查的采集时间、指令失效及评分数据，同时保留原验收目标。性能开销、与现有二进制的行为差异仍需测量。新构建将是**有独立名称和指纹的后端基线**，不声称与现有安装字节一致。
