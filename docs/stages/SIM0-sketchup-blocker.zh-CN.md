## 根因，以及对前次审核的纠正

完整日志显示 `Assets/Prefabs/OpenCAV/OpenCAV.prefab` 有七个缺失 prefab GUID。与最初导入日志对比后确认：这些诊断原先就存在，前次只汇总六项错误时漏报了它们，并非本次隔离造成。对应七个 `.skp` 源文件实际存在，因此没有继续简单排除资源，而是检查了真实导入结果。

扩展后的探针读取导入器类型、实际对象类型及局部文件 ID，发现问题同时影响**比赛场景必需资源**：

| 资源 | Linux 实际结果 | F1TENTH 序列化引用 |
| --- | --- | --- |
| `Proto Track.skp` | 通用 `AssetImporter`／`DefaultAsset`，没有导入对象。 | 16 处引用无法解析，包含网格引用。 |
| `Berlin Track.skp` | 同上，没有导入对象。 | 20 处引用无法解析。 |
| `F1TENTH.fbx`，作为对照 | 正常 `ModelImporter`，2,824 个对象，其中 564 个网格。 | 检查的 576 处引用全部可解析。 |

项目内检查到的 **50 个 `.skp` 文件均未生成网格对象**。Unity 2021.3 官方文档明确说明 Linux 不支持 SketchUp 导入，与本次固定编辑器的实际行为一致。仅更换 Ubuntu 版本无法补上这一导入能力。[Unity 2021.3 官方限制](https://docs.unity3d.com/2021.3/Documentation/Manual/class-SketchUpImporter.html#limitations)，访问日期 2026-09-29。

因此，前次仅比较依赖路径的审计不足以证明几何已成功导入。本次已记录此限制，并补充了可复用的导入器／对象检查。没有打开或保存场景，也没有修改运行代码、渲染器、车辆物理或传感器配置。

日志还保留了编译警告、无图形设备下的 shader 诊断以及 31 条 fallback shader 查找消息。对应 shader 源文件实际存在于固定 Shader Graph 包内，不能据此断言下载缺失；图形播放器中的实际影响仍未验证。九个孤立元数据删除和两个演示材质升级与前次一致，没有将其自动认定为运行通过。

**已安装的 AutoDRIVE 播放器仍保留此前已验证的可用范围。** 本次只读检查再次解析出 18 个碰撞网格与 120 个脚本身份，Proto 启用、Berlin 禁用。安装包内已有编译后的几何；当前问题是 Linux 从 `.skp` 源码重新构建这些资源。新播放器尚未生成。

## 待讨论的恢复路线

所有路线继续使用本机 Linux／ROS 2 Humble／AVLite 运行环境，下列内容尚未实施。

| 路线 | 收益 | 成本与剩余风险 | 对计划的影响 |
| --- | --- | --- | --- |
| **H：使用 Windows x86_64 构建主机，固定编辑器版本，输出 Linux 播放器后回本机测试。有主机时推荐。** | 保留源资源格式，避免重建赛道几何；上游本来就指定 Windows→Linux 工具链。 | 需要可用主机、用户处理许可、精确 Editor／Linux IL2CPP 模块、依赖下载与产物传输。该主机上的具体构建组合尚未验证。 | 增加主机预检和可移植构建入口，继续完整导入／引用／构建验收以及两次本机静止测试。未选择主机或上传文件。 |
| **P：取得权威的可移植赛道资源，或在支持的建模主机上转换，再回 Linux 构建。** | 资源验证完成后，日常构建和实验可留在本机。 | 必须检查拓扑、单位、变换、法线／UV、材质／子网格、碰撞体及引用；不能只改扩展名。OpenCAV 导入诊断仍需明确处理。 | 需单独审核资源准备补丁与等价性检查；当前未修改场景引用或替换资源。 |
| **L：先研究从本机安装包的编译后几何生成派生资源的可行性。** | 本地已有可读取的赛道几何，初步调查不依赖外部构建主机。 | 当前仅验证只读碰撞几何提取；完整渲染／碰撞重建、引用映射和可复现导入均未证明。来源与等价性验证负担最大，必须标识为派生后端。 | 先批准有限可行性调查和具体补丁建议；实际转换／替换需再审核后才能进入验收运行。 |

Unity 的工具链文档说明了 Windows 上输出 Linux IL2CPP 播放器的路线，但当前 `@2.0` 在线页面显示 **2.0.11**，不能据此声称已在 Windows 验证项目固定的 **2.0.4** 组合。这里没有升级软件包。[官方工具链文档](https://docs.unity3d.com/Packages/com.unity.toolchain.win-x86_64-linux-x86_64@2.0/manual/index.html)，访问日期 2026-09-29。

**建议：有可用 Windows 主机时选择 H；如果必须全程本地 Linux，先选择 P 的权威可移植输入或 L 的有限调查，再根据证据审核转换方案。** 不自动扩大排除范围，不继续重复无效的 Linux 导入，也不擅自迁移引擎或采用此前未采纳的 PRE 后置方案。

需要确认的依据是[已批准修订](../planning/simulator-build-amendment.md)中的“Fail on missing references”以及不得自动替换执行环境的边界。你最近的确认只覆盖六项非必需资源及元数据，没有覆盖替换必需赛道几何或切换构建主机。验收标准和两次静止试验保持不变。
