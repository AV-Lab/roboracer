## 车轮和速度证据的含义

两次运行、两个阶段的**全部选中样本**中，四轮均满足：电机扭矩 **0 Nm**、RPM **0**、转角 **0°**；制动扭矩 **85.599998474 Nm**，grounded 为 true；WheelCollider 返回的前向及侧向 slip 均为 **0**。

两次 FixedUpdate 数据合并后的接地点力范围约为：左前 **7.307–7.337 N**、右前 **7.296–7.318 N**、左后 **8.084–8.106 N**、右后 **8.065–8.095 N**。这验证了实际运行的零输入制动分支，但不能证明全部车辆碰撞体无滑移，也不能把零编码器读数当作车身静止证据。

车身 Z 位置以 **5.96046448×10⁻⁸ m** 的整数倍变化，单步为 −1 到 +3 个单位，存在局部回退。因此完整精度轨迹不是严格单调，尽管原协议量化后的 X 单调增加。把采集的步进前 Z 速度按固定步长求和，得到约 **0.010226／0.010228 mm**，明显小于位置变化 **3.437／3.259 mm**。利用车身位姿及源码中序列化质心计算，Z 位移基本相同；该计算假设源码质心赋值持续有效，运行时质心未独立采样。速度求和只是描述性比较，不是内部求解器恒等式，也不能证明某个具体缺陷。

**已验证事实：**车身位置变化、传感器局部偏移不变、零输入／制动分支生效、细微状态持续变化。**设计判断：**下一步应检查复合碰撞体接触及位置更新行为。**未知事项：**具体接触／数值机制、负载／赛道／指令下的表现，以及修复是否保持适用于竞速的动力学。

静态记录显示，`F1TENTH/Vehicle/{FL,FR,RL,RR} Wheel/Collider` 四个 convex MeshCollider 已启用，同时存在四个执行器 WheelCollider。`VehicleController.UpdateWheelPose` 每个物理回调更新前述网格的父车轮 Transform。凸包警告中提到的详细 `Wheel-N-solid1` MeshCollider 反而是**禁用**的，不能仅凭警告确定原因。当前 ground-hit 数据不含复合 MeshCollider 的接触对象身份。[碰撞体清单](../../artifacts/simulator-build/20261001T060743Z-kinematics/read-only-contact-inventory.json)、[源码及 API 复核](../../artifacts/simulator-build/20261001T060743Z-kinematics/next-contact-proposal-evidence.json)。

相较直接禁用车轮网格，这里建议使用指定碰撞体配对过滤，因为附属碰撞体可能影响自动计算的惯量；实际惯量仍需核验。[Unity 惯量文档](https://docs.unity3d.com/2021.3/Documentation/ScriptReference/Rigidbody-inertiaTensor.html)，访问 2026-10-01。准确版本的本地 PhysicsModule XML 包含 IgnoreCollision、读回及接触 API；另两个网页访问失败已如实记录，没有声称成功读取。

Proto 的 MeshCollider 包含整个赛道表面，因此 B 忽略的是这些车轮网格与**整个赛道碰撞体**之间的碰撞，不是只过滤地板三角形。该改变只适用于有界被动诊断，不具备竞速运行资格。

收益是增加带匹配观测对照的因果干预；成本是一次构建、接触工具和最多四次窗口，最新 **248.366 s** 构建耗时仅作参考。风险包括支撑行为改变、提前触发停止以及日志／启动差异造成混杂，失败须保留。更小的替代范围是只记录接触，但它不能确定去除接触配对的效果。直接放宽 P0 会在物理机制未解决时改变验收，当前不建议仅凭这些数据采用。

**需要你确认，是因为本次已批准的[只读范围](SIM0-neutral-drift.md#status-and-proposed-next-decision)不允许改变既有物理状态，并要求对进一步试验提出具体决策。拟议的配对过滤会改变碰撞行为，也超出已经完成的两次窗口预算。**P0 和“完整 PRE 后才进入 S1”的顺序保持不变。
